Bug: edges disagree on side (no crossing found) (31)

Root cause now understood precisely (2026-08-09), unifying this with no_closed_loop/empty_collection/the earlier disconnected-curve2-edge bug below: when a boundary edge's own two endpoints genuinely disagree on which side of a clip they're on, but the crossing-finder comes up empty, the code silently picks a side (cur_side tiebreak) instead of finding the true crossing point. That's not just wrong for *this* edge -- the tiebroken edge's own (non-crossing) endpoint can later get reused as a trace-edge boundary elsewhere, producing an edge whose recorded curve doesn't actually pass through its own vertex (confirmed directly: evaluate(edge.curve, edge_own_point) off by several units, not noise). Three concrete crossing-finder gaps behind the tiebreak firing were found and fixed this session: (1) curve_natural_axis assumed every curved edge is a parabola (rank-1) and used a shortcut invalid for the genuinely rank-2 hyperbolas that segment-vs-segment bisectors produce, silently rejecting real in-range crossings; (2) the conic-pencil root finder's companion-matrix eigenvalues were imprecise for a root far from its [-1,2,0,1] sampling range, now Newton-polished; (3) a near-tangent conic pair could report up to 7 near-duplicate "crossings" against a Bezout bound of 4, now resolved by refining each candidate onto the exact curve before deduping. All three are verified fixes (full test suite clean throughout) but the net effect on this specific 150-case stress suite is roughly neutral to slightly negative in raw pass count, because every case in this whole failure family shares the same one root cause -- closing one gap just shifts which case hits it. Remaining crossing-finder hardening is real, scoped, follow-up work, not a mystery anymore.

Bug: collection must be non-empty (insert_features!) (11)

A `first()` call on an empty collection inside `insert_features!` -- same exact stack trace across every case in this group, a strong signal of one shared cause, not yet traced further.

Bug: empty face-boundary loops -> MethodError (10)

`curved_face_local_frame` called with an untyped empty `Vector{Any}` -- happens when a face's own boundary decomposes into zero loops at all; a real (if narrow) type-safety gap, not yet fixed.

Bug: boundary forms no closed loop (dangling spike) (8)

Same root cause as disagree_on_side above (a missed crossing silently tiebroken instead of found), manifesting as a boundary walk with no genuine closed loop instead of a direct side-disagreement.

Skipped (degenerate: two endpoints under 1.0 apart) (4)

Not a bug: the random segment generator itself rejects any segment under 1.0 units long and redraws the trial, exactly like every other stress run this session.
