algorithm poster · 2d implemented, n-dimensional in design

Generalized Voronoi diagrams, built from one algebraic fact

Every input feature carries a squared-distance function that is quadratic in x. So every tie between two features — every bisector — is a quadric. The whole diagram is an arrangement of quadrics, assembled one feature at a time. That single fact is the entire algorithm; everything below is it playing out.

the one idea

A distance function that stays quadratic

Take any affine subspace of the input mesh — a vertex, a segment, in general a k-face — anchored at p with orthonormal direction basis B. Its squared distance to a point x is

sqdist(x) = |x − p|² − |Bᵀ(x − p)|²

— ordinary squared distance, minus the part already accounted for by the feature's own directions. It is exactly quadratic in x: K=0 (a point) recovers plain squared distance; K=N−1 (a hyperplane) recovers (n·x−d)². One formula, no case split, for every feature dimension.

Two features tie where their two quadratics are equal — an equation of the form xᵀMx + 2bᵀx + c = 0. A quadric, always. Nothing about the algorithm below assumes flat or curved; it assumes quadric, and asks which specific one.

what varies, case by case

The bisector's own matrix M is the difference of the two features' own Ms. Its rank — not the feature types themselves — decides what kind of curve results:

  • rank(M) = 0 — a hyperplaneboth features have the same quadratic part (e.g. two points: both M = I)
  • rank(M) = 1 — a parabola / paraboloidone point-like, one line-like feature: an irreducible curved bisector
  • rank(M) = 2, indefinite — a line pairtwo line-like features: (n_A·x−d_A)² = (n_B·x−d_B)² factors exactly into two straight lines

the data structure

Labels run opposite to containment

The input mesh is closed under taking subsets — every sub-simplex of a stored simplex is implicit — so storing only the ⊆-maximal simplices is lossless: a mesh has type P(P(VertexIdx)).

A cell's label is the set of input sub-simplices tied for the win there — one element of that same type, P(P(VertexIdx)), one level up. And here the direction reverses: where a boundary cell sits inside a higher cell in the mesh, its label is a superset of what it bounds. A cell with label {{6,7}} meeting a {{8}}-labeled neighbor shares a boundary labeled {{6,7},{8}}.

That reversal is what makes supercells free: everything a label L bounds is just the stored cells whose label is a subset of L — a direct powerset check, no index required. Subcells are the opposite: nothing bounds how many superset-labels can exist above a given cell, so they must be indexed as they're discovered during construction.

  • supercells — freeenumerate subsets of a label directly against the live label index
  • subcells — indexedtracked explicitly, populated as a byproduct of the recursion below

the construction

One recursion, one dimension at a time

Insert a new bisector by finding where it meets the existing skeleton one dimension down — itself the same problem, one level lower. It bottoms out at inserting an isolated point, which is trivial. The subcell index above falls out of this for free: discovering a hypersurface's own subcells is the recursive step.

k = 0

insert an isolated point into the 0-skeleton — the base case

→
k = 1 · implemented

insert a curve by finding where it crosses the existing 1-skeleton, at points

→
k = 2 · not yet

insert a surface by finding its trace on the existing 2-skeleton, as curves

→
k = 3 · not yet

insert a volume's own boundary against the existing 3-skeleton

2D is not a separate code path — it is this recursion with one fewer level. The six cases on this poster are all what k=1 actually looks like.

the generic cases, k = 1

What the recursion's base case actually produces

Every figure below is a real, minimal, off-screen render of the actual construction — not a mockup. generic is used throughout in the algebraic-geometry sense: an open, nonzero-measure set of configurations produces the case — the opposite of a coincidence like two exactly-parallel segments.

01
generic

Flat bisector

point vs. point. Both quadratics have M = I; the difference has M = 0. The bisector degenerates to a hyperplane — ordinary squared-distance-to-a-point recovers the classical (power) diagram as the K=0 special case of the one formula above.

02
generic

Curved bisector

point vs. line-interior. M becomes a rank-1 projector — a genuine paraboloid; a parabola at N=2. Its own axis (the projector's nonzero eigenvector) is exactly the line's own direction, and needs no eigendecomposition: for a rank-1 M, that eigenvector is literally M's own first row.

03
generic

Line-pair bisector

line-interior vs. line-interior. Squared-distance-to-a-line is already (n·x−d)², so the tie (n_A·x−d_A)² = (n_B·x−d_B)² factors exactly: n_A·x−d_A = ±(n_B·x−d_B) — two straight lines through their own crossing point, never one connected curve. Handled as two ordinary flat clips, not as a curve at all.

04
generic

Multi-crossing

a curved bisector can cross one existing edge twice. It dips into a cell and back out, carving an isolated island. Walk the cell's boundary in cyclic order, split each edge at its own 0, 1, or 2 crossings, cut the resulting cyclic sequence into maximal same-side runs, close each run with its own fresh arc.

05
generic

Quadric × quadric

a new bisector can have to cross an already-curved edge. In general, two quadrics with different M meet in up to four points (Bézout) — a hard problem. But every stored curved edge here ties the same feature its neighbor does, so the new bisector and the old edge always share one feature; their difference cancels it out, reducing to the same line-pair trick as case 03, one algebraic step removed.

06
generic

Multiply-connected cells

a cell's territory can be an annulus. Another live cell's region can end up entirely enclosed inside it — genuinely, not a corruption: nothing in the winner-comparison rules forces simple connectivity once curved bisectors are in play. Handled by decomposing a cell's boundary into all of its simple cycles, not just one, and treating every cycle but the largest as a hole to be carried through unchanged.

robustness, briefly

Exact predicates handle the boundary, not the geometry

Every sign decision — which side of a bisector, is this a genuine crossing — routes through an adaptive predicate: fast floating-point evaluation with a rigorous error bound, falling back to exact arithmetic only when that bound can't rule out a sign change. A genuine tie (not just a floating-point-apparent one) is broken by a fixed symbolic rule, so the same configuration never resolves two different ways.

This machinery is entirely about the measure-zero locus where two answers coincide exactly — parallel segments, an exact three-way tie. It has no bearing on the six generic cases above, which hold regardless of precision. Deliberately kept brief here for exactly that reason.

is it elegant, or a hodge-podge of cases?

Both — and not by accident

The kernel is genuinely elegant

One algebraic fact — squared distance to an affine subspace is quadratic, so every tie is a quadric — accounts for the entire construction. It is what makes the algorithm dimension-generic rather than a 2D trick with a 3D patch bolted on: nothing above assumes N=2, and the same recursion is the design for every dimension at once.

The label/subcell/supercell duality is not an implementation convenience layered on top; it falls directly out of the same recursion, for free, as it runs.

The realization has real seams

A quadric is a family, not one shape: parabola, line-pair, and hyperplane are the same equation at different ranks, and the degenerate rank (line-pair) genuinely needs its own dedicated code path — a structural, not arbitrary, case split.

Construction is incremental — one feature at a time, cell by cell, for interactivity — and that is the real source of seams: two independently-processed comparisons of the same new feature can disagree at their own shared boundary by more than rounding. This poster's own remaining open bug lives in exactly that seam.

An elegant, provably general foundation, wearing real case-handling machinery exactly where incrementality meets algebraic degeneracy — not scattered arbitrarily through the code, but concentrated precisely at the one structural pressure point the design creates.

what isn't built yet

Three dimensions: one more level of the same recursion

Nothing above assumes N=2 — the feature type, the quadric bisector type, the label duality, and the exact-predicate kernel are already dimension-generic. What's missing is genuinely new work, not a rewrite:

new

A richer quadric zoo

3D segment-vs-segment comparisons include pairings 2D never has to represent at all — e.g. a line against a plane. More species to classify, not a harder core idea.

new

k = 2: surface into the 2-skeleton

Inserting a bisector surface means first finding its own trace curve where it crosses the existing 2-skeleton — the one genuinely unimplemented step.

reused

k = 1: curve into the 1-skeleton

Once that trace curve exists, inserting it into the existing 1-skeleton is exactly the k=1 machinery on this poster, unchanged.

Tessellating curved surfaces for display is separately new, and orthogonal to construction — a renderer concern, not an algorithm one.
